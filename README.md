# sheet-writer

Google スプレッドシートへの書き込みで、**見切れ防止の書式をコードの構造で担保する**ための tool と検査役（checker）。

規約（正本はスキル `spreadsheet_cutoff_prevention`）は文章のルールとして存在したが、書き手が Sheets API を直接叩くときに「思い出すかどうか」へ依存し、実際に違反（折り返し未設定・行高不足）が発生した。本 tool は書式計算・設定・検証を機械的に行い、検証が通らなければエラーで返す（黙って成功にしない）。

数値の実体（文字幅・余白・行高の係数）は本リポジトリの設定（`config.example.json` の `measures`、コード側デフォルト）に置く。スキル側は指揮と要点のみを持つ。

## 何をするか

### 書き込み tool（`append`）

行追加を受け取り、次を機械的に行う。

1. 列幅を「ヘッダー＋全データ行の最長値」から再計算して設定する（全角1文字 ≒ 11.5px、半角 ≒ 6.3px、太字は 12 / 6.6px、余白 +20px。列ごとに `fit`（1行に収める）／`wrap`（固定幅で折り返す）のモードを設定で選ぶ）。**列幅は縮めない**（現行より小さくなる計算結果は採用しない）。
2. `wrap` 列には折り返し（WRAP）を設定する。
3. 行高を折り返し後の行数から設定する（行高 = 10 + 16 × 行数 px、最小 26px。ヘッダー行は 38px）。
4. 追加行の書式（背景色・配置・数値書式）は上の行に揃える。交互色（背景色が1行ごとに切り替わる）シートでは、同パリティの行の書式を使う。ただし背景色チェック（`background_rule`、後述）が有効な対象では、追加行へ背景色を持ち込まない。
5. 書き込み後に `columnMetadata` / `rowMetadata` と値・書式を読み戻し、意図どおりでなければ `VerificationError` で失敗する。検証では `textFormat` のサブキー（bold・italic・fontSize・fontFamily）も突き合わせる。

なお、**数式の継承・コピーダウンは本 tool の対象外**である。追加行に数式を付け足す処理は行わない（対象シートは数式列を持たない前提）。

末尾判定列（`append_anchor_column`、後述）が設定された対象では、追記位置を「anchor 列に値のある最終行の直後」としてシート状態から自分で計算し、書き込みは values append のテーブル検出に頼らず values update（`USER_ENTERED`）で A 列から正確な範囲へ直接書く。未設定の対象は従来どおり values append で追記する。

### 検査役（`check`）

既存シートを走査し、違反を検出して報告する。

- 列幅不足（`fit` 列で必要幅 > 現在幅。`wrap` 列も、設定された幅より現在の幅が狭ければ無条件に対象。現在幅が既定幅 100px の列や幅未設定の列も対象で、未設定は既定 100px として扱う）
- はみ出す内容があるのに折り返しが設定されていないセル
- 行高不足（推定必要行高 > 現在の行高）
- 背景色（`background_rule` が有効な対象のみ。後述）

`--fix` を付けると**書式のみ**（列幅・折り返し・行高・背景色の除去）を自動修正する。値・数式には絶対に触らない。自動修正は、対象として承認されたシート（タスク台帳など）でのみ使う。

### 背景色チェック（`background_rule`）

対象ごとに opt-in で有効化する書式ルール。設定で `"background_rule": true` とした対象では、データ行（2行目以降）のセルに背景色（`backgroundColor` または `backgroundColorStyle`）が設定されていたら違反にする。ヘッダー行は対象外で、**白（red=green=blue=1）の明示設定も違反**になる（未設定だけが正常）。`--fix` で違反セルの塗りを除去する（他の書式は保持する）。writer 側も有効時は追加行へ背景色を持ち込まず、追加行に背景が残っていたら検証エラーにする。無効（既定）の対象では従来どおり背景色を継承し、検査もしない。

### 末尾判定列（`append_anchor_column`）

一部の列だけ事前設定値が下の行まで続いているシート（例: チェックボックス列が200行目まで `FALSE` で埋まった台帳）では、「いずれかの列に値のある最終行」を末尾とみなすと追記位置・検査範囲がずれる。設定で `"append_anchor_column": "B"` のように末尾判定に使う列を指定すると、その列に値のある最終行をデータの末尾として扱う。

- writer: 追加位置は anchor 最終行の直後になり、書式はその行（追加位置の直上の行）から継承する。書き込みは values update で正確な範囲へ書く（前述）。
- checker: 検査対象のデータ行は anchor 最終行まで（行高・折り返し・背景色・列幅計算のすべてに一貫して適用）。それより下の行は対象外で、`--fix` も触らない。
- 検証: 指定できるのは大文字の列名のみ（`^[A-Z]+$`、例 `"B"`・`"AA"`）。小文字・数字・空白を含む値や空文字などは `ValueError` になる（CLI では終了コード 2）。

## 設定

`config.example.json` をコピーしてローカル設定を作る（実 ID を書いた設定ファイルは `*.local.*` として gitignore 対象にする。リポジトリに実値を書かない）。

- `measures`: 幅・高さの係数（規約スキルの確定値）
- `targets.<名前>`: `spreadsheet_id` / `tab` / 列ごとのモード（`fit` または `{"mode": "wrap", "width_px": 300}`）
- `targets.<名前>.background_rule`（任意・既定 `false`）: 背景色チェックを有効化する
- `targets.<名前>.append_anchor_column`（任意・既定なし）: 末尾判定に使う列（例 `"B"`、大文字の列名のみ）

設定の不備（必須キーの欠落、未知のキー、値の型の誤り）は `ValueError` として報告され、CLI は終了コード 2 で終わる。

## 使い方

前提: Google Sheets コネクタ（`hatch_gws_cli`）が接続済みの環境で実行する。

```bash
# 行追加（値は JSON 配列で渡す。複数行は --row を繰り返す）
python -m sheet_writer.cli append \
  --config config.local.json --target task-ledger \
  --row '["11","タスク名","待ち","理由テキスト","確認方法","2026-11-15","https://example.com/issue","2026-11-08"]'

# 検査（報告のみ）
python -m sheet_writer.cli check --config config.local.json --target task-ledger

# 検査＋書式のみ自動修正（承認されたシートでのみ）
python -m sheet_writer.cli check --config config.local.json --target task-ledger --fix
```

### タスク台帳への行追加（取りまとめ用手順）

台帳「Muse のタスク台帳」への行追加は、Sheets を直接編集せず本 tool の `append` を使う。列は No. / タスク / 状態 / 止まってる理由・前提条件 / 前提の確認方法 / 期日・次回確認日 / 関連リンク / 最終更新。複数文を入れるセルは「。」ごとに改行して渡す。

## 注意（実地確認で判明した点）

- 値の書き込みは `USER_ENTERED` のため、日時・数値らしい文字列は Sheets 側で解釈される。読み戻しの表示値（formattedValue）が整形されて書き込み文字列と異なっても、入力値（userEnteredValue）が同じ値を表していれば合格とする（数式は formulaValue、文字列は stringValue、数値・日付・時刻は numberValue＝日付・時刻は1899-12-30起点のシリアル値、真偽値は boolValue で照合する）。入力値が別の値を表す場合やセルが落ちている場合は、書き込み後の検証が不一致を検出してエラーで返す（黙って成功にはならない）。不正な形式の日時文字列など変換で化けた場合はこちらに該当する。化けた行が残ることがあるため、エラー時は対象行を確認すること
- 検査役は「内容のない行」を行高不足の対象にしない（グリッドの残り行は既定行高のままでよい）
